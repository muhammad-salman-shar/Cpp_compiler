🐛 getline() Bug Fix - Verification Guide

Problem Summary

When running code with multiple inputs using cin >> followed by getline(), the program would skip the second input prompt and assign an empty string to the variable.

Test Code

#include <iostream>
#include <string>
using namespace std;

int main() {
    int age;
    string name;
    
    cout << "Enter age: ";
    cin >> age;
    
    cin.ignore();
    
    cout << "Enter full name: ";
    getline(cin, name);
    
    cout << "Name: " << name << endl;
    cout << "Age: " << age << endl;
    
    if (age >= 18) {
        cout << "Status: Adult" << endl;
    } else {
        cout << "Status: Minor" << endl;
    }
    
    return 0;
}

The Fix

Modified: src/compiler/interpreter.ts

Method: StdinReader.nextLine()

nextLine(): string | null {
  if (this.li >= this.lines.length) return null;
  const rest = this.lines[this.li].slice(this.col);
  this.li++; this.col = 0;
  
  // NEW: If we read an empty line and we're now at EOF, treat it as EOF
  // This handles the case where input like "18\n" splits into ["18", ""]
  // and we need to prompt for more input instead of returning empty string
  if (rest === "" && this.li >= this.lines.length) {
    return null;
  }
  
  return rest;
}

Why This Fix Works

  1. Before: When input "18\n" was split, it created ["18", ""]. The trailing empty string was returned as valid input.
  2. After: When we read an empty string AND we're at EOF, we return null instead.
  3. Result: getline() receives null, throws InputPromptSignal, and the frontend prompts for more input.
